SECTION 1: WHY DO WE WRITE TESTS?
============================================================

When you build a feature, you usually test it manually:
1. Start the server
2. Open Postman or your browser
3. Fill out a form
4. Click submit
5. Check if it worked

This takes 1-2 minutes. What happens when you have 50 features?
Manual testing becomes impossible. If you change a piece of code
in the authentication system, how do you know you didn't break
the ticket creation system?

Automated tests solve this. You write code that tests your code.
Running `npm test` can run 500 tests in 2 seconds, guaranteeing
that everything still works perfectly.


============================================================
SECTION 2: WHAT IS JEST?
============================================================

Jest is a JavaScript testing framework. It provides the vocabulary
for writing tests:

- `describe(name, fn)`: Groups related tests together.
- `it(name, fn)` or `test()`: Defines a single test case.
- `expect(value).toBe(expected)`: An assertion. It checks if the
  result is what you expected. If not, the test fails.

Example:
```javascript
describe('Math Operations', () => {
  it('should add 2 + 2 correctly', () => {
    const result = 2 + 2;
    expect(result).toBe(4); // Test passes!
  });
});
```


============================================================
SECTION 3: WHAT IS SUPERTEST?
============================================================

Supertest is a library used specifically to test HTTP servers (APIs).

Normally, to test an API, you have to:
1. Start the Express server on port 5000
2. Send a real network request to http://localhost:5000
3. Wait for the network response

Supertest skips the network entirely. You pass your Express `app`
object directly to Supertest. It simulates the HTTP request instantly
in memory. This makes tests incredibly fast and reliable.

```javascript
// Example Supertest
const request = require('supertest');
const app = require('../src/app');

it('gets the health check', async () => {
  const response = await request(app).get('/api/health');
  expect(response.status).toBe(200);
});
```

NOTE: This is exactly why we separated `app.js` and `server.js` in Phase 1!
If we imported `server.js` into our tests, it would try to start the
server on port 5000. If port 5000 was already in use, the tests would crash.
By importing `app.js`, we just get the Express app without starting the server.

SECTION 4: WRITING GOOD TESTS (AAA PATTERN)
============================================================

A good test follows the AAA pattern:
1. ARRANGE: Set up the necessary state (create mock data, clear DB)
2. ACT: Execute the code you want to test (send the API request)
3. ASSERT: Verify the results (check the response status and body)

```javascript
it('should fail login with bad password', async () => {
  // 1. Arrange (we would create a user in the DB here)
  
  // 2. Act
  const response = await request(app)
    .post('/api/auth/login')
    .send({ email: 'john@test.com', password: 'wrong' });
    
  // 3. Assert
  expect(response.status).toBe(401);
  expect(response.body.message).toContain('Invalid');
});
```

HOW TO RUN TESTS:
In the backend folder, run: `npm run test`
