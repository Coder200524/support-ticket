============================================================
SECTION 1: WHAT IS NODEMAILER?
============================================================

Nodemailer is a library for Node.js that makes sending emails easy.
It acts like an "email client" (like Outlook or Gmail app) that lives
on your server.

To send an email, it needs to connect to an SMTP server.
SMTP (Simple Mail Transfer Protocol) is the standard protocol for
sending emails across the internet.


============================================================
SECTION 2: WHY USE A SERVICE ARCHITECTURE?
============================================================

We put all the email logic in a separate file: `email.service.js`.
Why didn't we just write it inside the controller?

1. Reusability: Multiple controllers might need to send a "Welcome" email.
   Instead of copying the code, they just call `sendWelcomeEmail(user)`.
   
2. Clean Controllers: Controllers should focus on HTTP requests and responses.
   Moving complex logic into services keeps controllers readable.
   
3. Easy Swapping: If we decide to switch from Nodemailer to a service like
   SendGrid or AWS SES later, we only have to change ONE file.


============================================================
SECTION 3: HOW IT WORKS (THE CODE)
============================================================

1. The Transporter
First, we tell Nodemailer HOW to send the email:
```javascript
const transporter = nodemailer.createTransport({
  host: process.env.EMAIL_HOST,
  port: process.env.EMAIL_PORT,
  auth: {
    user: process.env.EMAIL_USER,
    pass: process.env.EMAIL_PASS,
  },
});
```

2. Sending the Email
Then we tell it WHAT to send:
```javascript
await transporter.sendMail({
  from: '"Support System" <noreply@support.com>',
  to: "user@example.com",
  subject: "Ticket Created",
  html: "<h1>We got your ticket!</h1>", // HTML body
});
```

3. Non-Blocking Execution
Notice how we call it in the controller:
```javascript
// Send email, but don't await it!
sendTicketCreatedEmail(user, ticket).catch(console.error);

return sendSuccess(res, ...);
```
We do NOT `await` the email function. Sending an email over the internet
can take 1-3 seconds. We don't want the user to stare at a loading spinner
waiting for the email to send. We fire it in the background and immediately
send the success response back to the user.


============================================================
SECTION 4: TESTING EMAILS (MAILTRAP)
============================================================

When developing locally, you DO NOT want to send real emails.
You might accidentally spam a real user while testing!

We use a service called Mailtrap (https://mailtrap.io).
It acts as a "fake" SMTP server. You configure your app to send
emails to Mailtrap, and Mailtrap "catches" them all and displays them
in a dashboard, regardless of who the `to:` address was.

This is why our `.env` file uses Mailtrap credentials for development.
In production, you would swap these out for a real provider like
SendGrid, Mailgun, or Amazon SES.
